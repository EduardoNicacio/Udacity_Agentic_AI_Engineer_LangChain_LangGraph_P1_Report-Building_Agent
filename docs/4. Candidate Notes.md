# Candidate Notes

## Architecture Overview

The Report-Building Agent is a multi-agent document processing system built with LangChain and LangGraph. It uses a directed graph workflow where user input is first classified by intent, then routed to the appropriate specialized agent, and finally the conversation memory is updated before returning the response.

**Key Components:**

| Component | File | Purpose |
| :--- | :--- | :--- |
| **Schemas** | `schemas.py` | Pydantic models for structured data: `AnswerResponse`, `UserIntent`, `SummarizationResponse`, `CalculationResponse`, `UpdateMemoryResponse` |
| **Prompts** | `prompts.py` | Prompt templates for intent classification, QA, summarization, calculation, and memory summarization |
| **Tools** | `tools.py` | LangChain tools: calculator, document search, document reader, document statistics; plus `ToolLogger` for persistence |
| **Retrieval** | `retrieval.py` | `SimulatedRetriever` with in-memory document store supporting keyword, type, and amount-based retrieval |
| **Agent** | `agent.py` | LangGraph `StateGraph` with nodes for intent classification, three agent branches, and memory update; `AgentState` TypedDict tracks all state |
| **Assistant** | `assistant.py` | `DocumentAssistant` class managing sessions, LLM initialization, and end-to-end message processing |

**Graph Flow:**

```txt
classify_intent --> [qa_agent | summarization_agent | calculation_agent] --> update_memory --> END
```

The workflow uses `MemorySaver` as a checkpointer for persistent state across invocations within a session, and `operator.add` as a reducer on `actions_taken` to accumulate node execution history.

## Design Decisions

1. **Structured Output via Pydantic**: Used `llm.with_structured_output(Schema)` for intent classification and memory updates to get reliably typed LLM responses instead of parsing free-form text.

2. **ReAct Agent Pattern**: Each specialized agent (qa, summarization, calculation) uses `create_react_agent` from LangGraph, which allows the LLM to reason and use tools iteratively before producing a structured response.

3. **Simulated Retriever**: Rather than requiring a vector database, the system uses an in-memory document store with keyword matching, type filtering, and amount-based range queries. This makes the system self-contained and testable without external dependencies.

4. **Memory via Checkpointer**: Using `MemorySaver` (LangGraph's in-memory checkpointer) enables conversation persistence across multiple workflow invocations within a session, without requiring a database.

5. **Tool Logging**: The `ToolLogger` class automatically persists tool usage history to JSON files, enabling debugging and audit trails. Each tool call is logged with timestamps, inputs, and outputs.

6. **Safety Validation**: The calculator tool validates mathematical expressions with a regex whitelist before calling `eval()`, rejecting any input containing non-mathematical characters.

7. **Intent-Based Routing**: The `classify_intent` node uses LLM-based classification with a structured `UserIntent` schema that constrains output to valid intent types and includes confidence scoring.

## How the System Works

1. **Session Start**: The user creates a session via `DocumentAssistant.start_session()`, which generates a unique session ID and initializes a `SessionState`.

2. **Message Processing**: When the user sends a message, `process_message()` constructs the initial `AgentState` and invokes the LangGraph workflow with a config containing the thread ID, LLM, and tools.

3. **Intent Classification**: The `classify_intent` node formats the user input and conversation history into a prompt, invokes the LLM with structured output (`UserIntent` schema), and routes based on the classified intent:
   - `"qa"` -> `qa_agent`
   - `"summarization"` -> `summarization_agent`
   - `"calculation"` -> `calculation_agent`
   - default -> `qa_agent`

4. **Agent Execution**: The selected agent node:
   - Retrieves the appropriate system prompt via `get_chat_prompt_template()`
   - Constructs messages with user input and chat history
   - Invokes `invoke_react_agent()` which creates a ReAct agent with bound tools and structured output schema
   - The agent can search documents, read documents, calculate, and gather statistics as needed
   - Returns updated state with messages, response, and tools used

5. **Memory Update**: The `update_memory` node summarizes the conversation and extracts active document references using the `UpdateMemoryResponse` schema, maintaining context across turns.

6. **Response**: The final state is returned to the caller with the assistant's response, intent classification, tools used, sources, and actions taken.

## Automated Tests

The project uses `pytest` as its test runner. All test files are located under the `tests/` directory.

### Running Tests

From the project root directory:

```bash
# Run all tests with verbose output
python -m pytest tests/ -v

# Run a specific test file
python -m pytest tests/test_schemas.py -v

# Run a specific test class
python -m pytest tests/test_tools.py::TestCalculatorTool -v

# Run a specific test
python -m pytest tests/test_agent.py::TestShouldContinue::test_returns_qa_agent -v
```
